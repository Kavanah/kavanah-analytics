.. _api-authentication:

Authentication Endpoints
=========================

These endpoints handle session creation (login), session termination (logout), and
multi-factor authentication (MFA) challenge and setup.

----

.. http:get:: /login

   Renders the DEAM asset manager login page (HTML).

   :statuscode 200: Login form rendered.
   :statuscode 302: Redirects to the main page if already authenticated.

----

.. http:post:: /login

   Authenticates a user and creates a session.

   **Form parameters:**

   :form username: The user's Elasticsearch security username.
   :form password: The user's password.
   :form csrf_token: CSRF token from the login form hidden field.

   :statuscode 302: Redirect to main page on success, or to MFA challenge if 2FA is enabled.
   :statuscode 401: Invalid credentials.
   :statuscode 429: Too many failed attempts. Locked for 15 minutes.

   **Notes:**

   - If the user has MFA enabled, ``mfa_pending = True`` is set in the session and
     the response redirects to ``/mfa/challenge`` (or ``/mfa/setup`` for first-time enrollment).
   - A request carrying an ``X-Remote-User`` header (set by a header-asserting SSO
     proxy) is accepted without a password check only when the full proxy chain is
     proven: ``TRUST_NGINX_HEADERS=true``, the TCP peer address is listed in
     ``TRUSTED_PROXY_IPS``, and the proxy presents the shared ``PROXY_AUTH_SECRET``
     in ``X-Proxy-Auth``. See :ref:`nginx-sso-flow`. The form login falls back to
     Elasticsearch Basic Auth if headers are absent.

----

.. http:get:: /dashboards/login

   Renders the dashboard-only login page (HTML). For users who need access to
   dashboards but not the asset manager.

   :statuscode 200: Login form rendered.
   :statuscode 302: Redirects to dashboards page if already authenticated.

----

.. http:post:: /dashboards/login

   Authenticates a dashboard viewer and creates a session.

   :form username: The user's username.
   :form password: The user's password.
   :form csrf_token: CSRF token from the login form.

   :statuscode 302: Redirect to dashboards page on success, or to MFA challenge.
   :statuscode 401: Invalid credentials.
   :statuscode 429: Rate limited.

----

.. http:get:: /logout

   Clears the current session and redirects to the login page.

   :statuscode 302: Always redirects to ``/login``.

----

.. http:get:: /mfa/challenge

   Renders the MFA challenge page (HTML). Only accessible when ``mfa_pending = True``
   is set in the session.

   :statuscode 200: MFA challenge form rendered.
   :statuscode 302: Redirects to login if no MFA pending session.

----

.. http:post:: /mfa/challenge

   Verifies the submitted MFA code.

   :form code: A 6-digit TOTP code **or** a YubiKey OTP string. The server detects
     which type based on the length and format of the submitted value.
   :form csrf_token: CSRF token.

   :statuscode 302: Redirect to the main page on success.
   :statuscode 401: Invalid code. Returns to the challenge page with an error message.

   **TOTP:** 6-digit numeric code from the user's authenticator app. Valid for 30 seconds.

   **YubiKey OTP:** A 44-character modhex string generated by the YubiKey hardware.
   Validated against the Yubico OTP API (requires ``YUBICO_CLIENT_ID`` and
   ``YUBICO_SECRET_KEY`` environment variables).

----

.. http:get:: /mfa/setup

   MFA enrolment landing page. Lets the user pick **TOTP** or
   **YubiKey** themselves (admins no longer pre-select the
   method).

   Only accessible while ``mfa_pending = True`` and the user has not
   yet enrolled.

   :statuscode 200: Method-picker page rendered.

----

.. http:get:: /mfa/setup/choose

   Method-picker form (TOTP vs YubiKey).

.. http:post:: /mfa/setup/choose

   Persists the user's chosen MFA method and redirects to the matching
   setup page.

   :form method: ``totp`` or ``yubikey``.
   :form csrf_token: CSRF token.

   :statuscode 302: Redirect to ``/mfa/setup/totp`` or
     ``/mfa/setup/yubikey``.

----

.. http:get:: /mfa/setup/totp

   Renders the TOTP enrollment page. Generates a new TOTP secret and displays
   a QR code for scanning with an authenticator app.

   The QR code encodes an ``otpauth://totp/`` URI with:

   - **Issuer:** ``Kavanah Analytics``
   - **Account:** The user's username

   The TOTP secret is **not** persisted to Elasticsearch until the user
   confirms a valid code via ``POST /mfa/setup/totp/confirm``
   .

   :statuscode 200: TOTP setup page rendered with QR code.

----

.. http:post:: /mfa/setup/totp/confirm

   Confirms TOTP enrollment by verifying the first code from the user's
   authenticator app.

   :form code: The 6-digit TOTP code from the authenticator app.
   :form csrf_token: CSRF token.

   :statuscode 302: Redirect to main page on success.
   :statuscode 400: Invalid or expired code. The TOTP secret is stored only after
     successful confirmation.

----

.. http:post:: /mfa/setup/yubikey

   Registers a YubiKey by submitting its OTP. The YubiKey's public ID is extracted
   from the OTP and stored in the user's MFA record.

   :form otp: The YubiKey OTP string generated by tapping the key.
   :form csrf_token: CSRF token.

   :statuscode 302: Redirect to main page on successful registration.
   :statuscode 400: OTP validation failed (invalid format or Yubico API error).

.. _nginx-sso-flow:

Nginx SSO Flow
--------------

Kavanah Analytics can accept an identity asserted by an upstream reverse proxy via
the ``X-Remote-User`` header. The header path is **disabled by default** and, since
, is only honored when the deployment proves the proxy hop — all three of:

1. ``TRUST_NGINX_HEADERS=true`` (defaults to ``false``),
2. the request's TCP peer address is in the ``TRUSTED_PROXY_IPS`` allowlist, and
3. the proxy presents the shared secret from ``PROXY_AUTH_SECRET`` in an
   ``X-Proxy-Auth`` header (compared in constant time).

``TRUSTED_PROXY_IPS`` and ``PROXY_AUTH_SECRET`` default to empty, so setting
``TRUST_NGINX_HEADERS=true`` alone does nothing — the branch is inert unless a
deployment deliberately configures the full chain.

When the hop is proven, the application creates a session for the user named in
``X-Remote-User``. The user's roles are always resolved from Elasticsearch
Security; the ``X-Remote-Roles`` header is ignored. A request that presents
``X-Remote-User`` without the proven hop is treated as unauthenticated (it falls
through to the normal login redirect) and is logged as an audit warning with the
peer address.

.. note::

   The standard deployment does not use this flow at all: live SSO is Entra ID
   OAuth, nginx does not set these headers, and the Flask ports are
   bound to loopback so the apps are only reachable through nginx or on-host.

Self-service registration
-------------------------

.. http:get:: /signup

   Renders the self-service registration form. Only accessible when
   ``REGISTRATION_ENABLED=true`` in the deployment config.

   :statuscode 200: Signup form rendered.
   :statuscode 404: Returned when registration is disabled.

.. http:post:: /signup

   Submits a registration request. Stores the user as a *pending
   registration* in the ``de_pending_registrations`` index and emails
   the user a verification link.

   :form username: Desired username (3-30 chars, alphanumeric +
     underscore/hyphen/dot).
   :form email: Email address.
   :form password: Password (12+ chars, mixed case, digit, special
     character).
   :form csrf_token: CSRF token.

   :statuscode 302: Redirect to ``/signup/success`` on success.
   :statuscode 400: Validation error.
   :statuscode 429: Rate-limited (5 registrations per IP per hour).

.. http:get:: /verify-email/(token)

   Verifies a registration via the token in the verification email.
   On success, marks the pending registration as *Pending Approval*
   so an admin can approve it.

   :statuscode 200: Verification page rendered.
   :statuscode 400: Token expired or invalid.

----

Password change
---------------

.. http:get:: /change-password

   Renders the password change form. Used both for the forced
   first-login change and for users picking a new password mid-session.

   :statuscode 200: Form rendered.

.. http:post:: /change-password

   Submits a password change. Requires the current password (unless the
   session is in ``fpc_pending`` state from forced first-login).

   :form current_password: Current password (omitted on forced change).
   :form new_password: New password.
   :form csrf_token: CSRF token.

   :statuscode 302: Redirect to home on success.
   :statuscode 400: Validation error or wrong current password.

----

Profile-side MFA enrolment
--------------------------

Users can enrol or change their own 2FA method from the **Profile**
page (``/profile``) without admin involvement, using these endpoints.
The flow mirrors the admin-triggered ``/mfa/setup/*`` flow but doesn't
require ``mfa_pending`` to be set.

.. http:post:: /profile/mfa/totp/setup

   Generates a fresh TOTP secret and QR code for the current user.

.. http:post:: /profile/mfa/totp/confirm

   Confirms the TOTP code, persists the secret, marks 2FA as enrolled.

.. http:post:: /profile/mfa/yubikey/setup

   Starts a YubiKey enrolment.

.. http:post:: /profile/mfa/yubikey/register

   Registers the YubiKey OTP and persists the public ID.

.. http:post:: /profile/mfa/disable

   Disables 2FA for the current user. Subject to ``ENFORCE_MFA``: if
   enforcement is on, the user must immediately re-enrol on the next
   request.

   :form current_password: Required as a re-authentication step.
   :form csrf_token: CSRF token.
