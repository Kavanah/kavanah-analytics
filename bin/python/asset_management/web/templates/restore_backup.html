ES Snapshots

Native Elasticsearch snapshots from registered _snapshot repositories (e.g. daily_repo, migration_repo). Lets you inspect what indices a snapshot contains and restore only the ones you select — no docker stop, no full data-dir swap. Use this for cherry-picking indices, cross-environment data syncs, or restoring accidentally-deleted indices.

Local Asset Backups

On-demand JSON snapshot of de_asset* indices (teams, accounts, integrations, dashboards). Use as a quick fail-safe before bulk edits in Asset Explorer — ES snapshots only run once a day. The 5 most recent are kept; older are auto-pruned on each new backup.

S3 Full Data Backups

Complete Elasticsearch data directory snapshots stored cross-account in AWS S3. Disaster-recovery only — for when this VPS is gone and the local SLM snapshots are gone with it. For routine restores prefer the ES Snapshots section above.

Full restore — replaces all data. Restoring an S3 backup will stop Elasticsearch, replace the entire data directory with the backup, and restart. All current data will be moved to a backup location. This takes several minutes and causes temporary downtime.

S3 Config Backups

ELK stack configuration snapshots for disaster recovery. Contains docker-compose config, Elasticsearch and Kibana settings, Python scripts, crontabs, and system info. Download & extract a backup to inspect its contents, then optionally apply selected files back to /app/reporting_configs on disk.
