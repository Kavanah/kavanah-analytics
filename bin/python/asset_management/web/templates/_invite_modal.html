{# Invite teammates modal. Sender-side surface that consumes the `?invite=open` query flag and the `invite_teammate` checklist row. Rendered unconditionally on the dashboard so the JS can pop it open for any authenticated user; visibility is controlled by `.invite-modal.is-open`. Inline state blocks (one visible at a time, JS toggles via `data-state` on the modal root): * form — initial form (default) * sending — submit in flight (button disabled, spinner) * sent — success after a fresh send * resent — success after a Resend on an existing pending * pending-prompt — server says pending exists, show Resend/Cancel * already-member — server says email is in the workspace * error — generic / network / SMTP failure Role options match the workspace roles the inviter can grant. Until wires `Permission.USER_INVITE` enforcement, the dropdown surfaces the four system roles the checklist already mentions in copy ("Editor" default per the AC). When lands, this list becomes a server-rendered slice of grantable roles for the inviter. #}
