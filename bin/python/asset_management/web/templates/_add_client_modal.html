{# Add Another Client modal. Agency-only surface that consumes the `add_client` checklist row. Renders unconditionally on the dashboard so the JS can pop it open for any authenticated user; visibility is controlled by `.add-client-modal.is-open` and the row only appears in the checklist for users where `is_agency_for_user` is True. The server endpoint (`POST /api/clients`) defends in depth with the same check. Stripped-down step-3-style form: client name + currency only. Other workspace fields (timezone, fiscal year start, slug check) belong to the wizard's initial setup; adding a 2nd / 3rd / Nth client doesn't need to re-collect them. Inline state blocks (one visible at a time, JS toggles via `data-state` on the modal root): * form — initial form (default) * sending — submit in flight (button disabled, spinner) * created — success after a fresh add * exists — server says the same-titled client is already under this workspace (idempotent re-POST) * error — generic / network / 500 failure #}
